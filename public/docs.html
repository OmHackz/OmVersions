Getting started

OmVersions is a centralized version management API that automatically fetches GitHub releases for registered projects. Projects are registered exclusively in projects.json at the repository root. Adding a project requires editing only that file; no route registration or code changes are necessary.

Registering a project

Add an entry to projects.json:

{
  "projects": [
    {
      "id": "myproject",
      "repo": "https://github.com/username/myproject"
    }
  ]
}

Optional fields: displayName, description, website. The original two-field format remains fully supported. Project IDs are normalized to lowercase and must match ^[a-z0-9](?:[a-z0-9-]{0,61}[a-z0-9])?$. Duplicate IDs and malformed repository URLs are rejected.

Release channels

Supported channels: stable, beta, alpha, rc, nightly. Stable is the default. Channels are classified from the release tag using this convention:

ChannelTag examples
stablev1.0.0, 1.2.0
betav1.1.0-beta.1
alphav1.2.0-alpha.2
rcv2.0.0-rc.1
nightlyv2.1.0-nightly.20261106

Unrecognized prerelease identifiers are treated as prereleases and are never classified as stable. Draft releases are ignored. GitHub's prerelease field is combined with the tag convention for classification.

Update checking

GET /api/v1/:id/check?current=1.0.0&channel=stable uses proper semantic version comparison, so 1.10.0 is correctly recognized as newer than 1.9.0. Optional v prefixes are supported. Invalid versions return INVALID_VERSION.

Example: desktop application update check on startup

async function checkForUpdate(projectId, currentVersion) {
  const res = await fetch(
    `https://version.omhackz.top/api/v1/${projectId}/check?current=${encodeURIComponent(currentVersion)}&channel=stable`
  );
  const json = await res.json();
  if (!json.success) return null;
  return json.data; // { project, currentVersion, latestVersion, updateAvailable, releaseUrl }
}

Caching

Successful GitHub release responses are cached with a default TTL of 5 minutes, configurable via the RELEASE_CACHE_TTL variable. Cloudflare Workers Cache API is not globally replicated between all data centers, so cache hits are local to the serving data center. Version information eventually updates without manual intervention.

Client integration examples

JavaScript / TypeScript

const res = await fetch("https://version.omhackz.top/api/v1/helio/latest");
const json = await res.json();
// json.data.version, json.data.assets, json.data.releaseUrl

Java

HttpClient client = HttpClient.newHttpClient();
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://version.omhackz.top/api/v1/helio/latest"))
    .build();
HttpResponse response = client.send(request, HttpResponse.BodyHandlers.ofString());
// Parse response.body() with Jackson/Gson

Python

import requests

response = requests.get("https://version.omhackz.top/api/v1/helio/latest")
data = response.json()["data"]
version = data["version"]
assets = data["assets"]

Rust

let client = reqwest::Client::new();
let resp: serde_json::Value = client
    .get("https://version.omhackz.top/api/v1/helio/latest")
    .send()
    .await?
    .json()
    .await?;
let version = resp["data"]["version"].as_str().unwrap();

Deployment

OmVersions runs on Cloudflare Workers. Install dependencies, build, and deploy: 

npm install
npm run build
npm run deploy

Attach the custom domain version.omhackz.top through the Cloudflare dashboard under Workers &rarrow; Your domain, or add a CNAME record pointing to your Workers route. Deployment uses CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID secrets via GitHub Actions.
